Detailed Description

Demonstration of RTOS Mutex Watchdog mechanism to detect deadlock or prolonged locks.

Illustrates how yss OS monitors mutex lock contention and invokes mutexWatchdogHandler() when a thread waits on a locked Mutex longer than THREAD_WATCHDOG_OVERFLOW_TIME (1000 ms).

Function Documentation

◆ main()

int main ( void )

Initializes the yss OS kernel and board hardware. Spawns a background worker thread (thread_testMutexWatchdog) and repeatedly toggles the LED while locking and unlocking gMutex at fast 100 ms intervals. When the worker thread locks gMutex indefinitely after 5 seconds, the main thread's next gMutex.lock() call blocks for more than 1000 ms and triggers mutexWatchdogHandler().

◆ mutexWatchdogHandler()

void mutexWatchdogHandler ( void )

Custom recovery handler invoked when a mutex lock exceeds THREAD_WATCHDOG_OVERFLOW_TIME.

Handler invoked automatically by the yss OS scheduler when a thread attempts to lock a mutex that remains held beyond the THREAD_WATCHDOG_OVERFLOW_TIME (1000 ms) threshold. Overrides the default weak reset handler and blinks the indicator LED in a slower 500 ms emergency cycle (compared to the normal 100 ms cycle) to signal deadlock detection.

◆ thread_testMutexWatchdog()

void thread_testMutexWatchdog ( void )

Thread entry point designed to induce a mutex deadlock / watchdog trigger.

Waits 5000 ms after system startup to allow normal fast LED blinking to be observed, and then locks gMutex without ever unlocking it. This simulates a hung thread holding a critical resource and causes the main thread to trip the 1000 ms mutex watchdog timeout.
