Initializes the hardware CRC engine in CRC32 mode:

  • Polynomial mode: CRC-32 (Crc::CRC_MODE_CRC32, polynomial 0x04C11DB7)
  • Data write width: 32-bit words (Crc::CRC_DAT_LEN_32BIT)
  • Initial polynomial seed: 0xFFFFFFFF
  • Bit order reversal: Disabled (false) for both input write data and output checksum
  • Enables the AHB clock for the CRC peripheral, applies the register configuration, and enables the CRC peripheral interrupt service routine.

Custom recovery handler invoked when a mutex lock exceeds THREAD_WATCHDOG_OVERFLOW_TIME.

Parameters
[in]none
Returns
none
Author
Yoon-Ki Hong
Date
2026-11-18
Warning
Overrides the default yss OS weak handler (which performs a system reset) with an infinite alarm blink loop.
Note
Toggles the on-board LED at 500 ms intervals to visually signal a detected mutex deadlock.
Precondition
THREAD_WATCHDOG_ENABLE must be set to true in config.h.
Postcondition
Execution remains in the emergency LED blink loop until reset.
Deprecated
none

Handler invoked automatically by the yss OS scheduler when a thread attempts to lock a mutex that remains held beyond the THREAD_WATCHDOG_OVERFLOW_TIME (1000 ms) threshold. Overrides the default weak reset handler and blinks the indicator LED in a slower 500 ms emergency cycle (compared to the normal 100 ms cycle) to signal deadlock detection.

See also
gMutex, setLed, thread::delay

Deliberately holds gMutex without releasing to trigger mutexWatchdogHandler().
Note
Waits 5 seconds before locking the shared mutex indefinitely.
Precondition
gMutex must be initialized and THREAD_WATCHDOG_ENABLE must be enabled in config.h.
Postcondition
gMutex is locked indefinitely by this thread, causing a watchdog timeout on waiting threads.
Deprecated
none

Waits 5000 ms after system startup to allow normal fast LED blinking to be observed, and then locks gMutex without ever unlocking it. This simulates a hung thread holding a critical resource and causes the main thread to trip the 1000 ms mutex watchdog timeout.
